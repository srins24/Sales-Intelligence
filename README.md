# Sales Performance Intelligence (simulated)

A Streamlit dashboard for sales managers at a logistics business. It shows revenue performance,
regional and customer trends, service mix, a forecast with a backtest, and rule-based management insights,
with an Excel export that follows the current filters.

> **All data is simulated.** The dataset is generated by `data_gen.py` with a fixed seed. It is not DHL company
> performance. The colour scheme takes inspiration from DHL's red and yellow. This project is not affiliated
> with or endorsed by DHL.

## What it covers

| Section | Contents |
|---|---|
| Executive overview | Total revenue, shipments, revenue per shipment, active customers, growth vs prior period, target achievement; monthly revenue against target |
| Regional analysis | Choropleth by country, regional comparison, highest and lowest performers, country and region tables |
| Customer analysis | Top 10 customers, segmentation (segment, value tier, Active / At risk / Churned), repeat shipping, monthly retention and lapsed share |
| Service analysis | Revenue, shipments and revenue per shipment by service, with category totals |
| Sales forecast | Six-month forecast (3 to 6 selectable) with an approximate 90% band, forecast against target, and a backtest on held-out months |
| Management insights | Rule-based findings (declining regions, missed targets, churn, concentration, service mix, forecast gaps) with recommended actions |

Sidebar filters: period (from and to month), region, service and customer segment. The Excel report (multiple sheets, README
sheet included) is built from the same filters.

## How it is built

```
data_gen.py     Simulated customers, shipments and targets, written to SQLite
db.py           SQL access layer (tables and the fact_sales view)
analytics.py    Pure pandas and NumPy analysis: KPIs, segmentation, retention, forecasting, insights, export
app.py          Streamlit interface and Plotly charts
tests/          pytest checks for analysis, data generation and every page of the app
```

- **Data storage and querying:** SQLite, with a `fact_sales` view that joins shipments to customers and services.
- **Analysis:** pandas and NumPy. Forecasting is a linear trend multiplied by calendar-month seasonality, chosen for
  transparency. It is a baseline, not a driver-based plan.
- **Interface:** Streamlit with Plotly charts. Filters are cached with `st.cache_data`.

## Definitions

- **Revenue growth:** selected period against the same number of months immediately before it.
- **Target achievement:** revenue against region targets. Shown only when all services and segments are selected,
  because targets are set by region and not by service.
- **At risk:** revenue in the last three months is under half of the three months before.
- **Churned:** no shipments in the last three months of data.
- **Retention:** share of last month's active customers who also shipped this month. Lapsed is the complement.

## Run it locally

```bash
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

The first run builds `data/sales_simulated.db`. To rebuild it manually: `python data_gen.py`.

Run the tests with `python -m pytest -q`.

## Limitations

- Synthetic data only. Patterns, churn and seasonality are modelled assumptions, so the figures do not describe any real business.
- Insight thresholds are judgement calls. They are listed in the app and can be changed in `analytics.py`.
- The forecast has no external drivers such as pricing, capacity or macro indicators.
